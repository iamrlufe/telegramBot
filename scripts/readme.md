# scripts/ — то, что выполняется на самих серверах

Здесь лежат **обезличенные образцы** скриптов, которые бот запускает на
серверах, а не код бота. В контейнеры этот каталог не копируется.

Зачем он появился. Скрипты копирования жили только на боевых серверах:
путь к ним записан в `copy_script`, но самих файлов не было нигде, кроме
как на диске сервера-источника. Сервер переставили — восстанавливать
нечего, а бот при этом ждёт от скрипта вполне определённых вещей: код
возврата, раскладку журналов и опорные строки в них. Образец эту дыру
закрывает и заодно служит спецификацией.

## Что здесь

| Файл | Что делает |
|---|---|
| `example.upload_common.cmd` | Возит копии MSSQL на приёмник по SFTP через WinSCP. Тип копии — аргументом: `FULL` или `DIFF`. Вся работа здесь. |
| `example.upload_full.cmd` | Обёртка: вызывает общий скрипт с `FULL`. Путь к ней идёт в `copy_script` под ключом `D`. |
| `example.upload_diff.cmd` | То же с `DIFF`, ключ `I`. |

Обёртки нужны потому, что `copy_script` — карта «тип копии → скрипт»:
у полной и разностной разные каталоги на приёмнике и разное расписание,
и бот ведёт для каждой свою очередь.

## Как поставить на сервер

1. Скопировать файлы на сервер-**источник** (тот, где SQL пишет копии),
   убрав приставку `example.`: обёртки зовут соседний `upload_common.cmd`.
   Обычное место — `C:\Scripts\`.
2. Открыть `example.upload_common.cmd` и заполнить блок «Настройки»:
   корень с копиями, сохранённая сессия WinSCP, путь к `WinSCP.com`,
   корень на приёмнике.
3. Завести сессию WinSCP **под той же учётной записью**, от которой бот
   ходит по WinRM: сессии лежат в профиле пользователя, и из-под другой
   учётки их просто не видно — скрипт упадёт на первой же строке.
4. Прописать пути в `servers.json` (проще из бота: ⚙️ Настройка →
   сервер → 📤 Копирование):

```json
"copy_script": {
  "D": "C:\\Scripts\\upload_full.cmd",
  "I": "C:\\Scripts\\upload_diff.cmd"
}
```

5. Проверить кнопкой 💾 Бэкапы → 📤 Копирование → «📤 Скопировать сейчас».

## Чего менять нельзя

Бот разбирает журнал скрипта (`shared/copy_log.py`), и часть его —
контракт, а не оформление:

- **раскладка журналов.** Рядом со скриптом `logs\<ГГГГ-ММ-ДД>\`, в нём
  `common_FULL.log` (или `common_DIFF.log`) и подкаталог на каждую базу
  с выводом WinSCP. Путь бот вычисляет по пути к скрипту, настройки для
  этого нет;
- **штамп времени** `[05.09.2026 11:17:42,07]` — то есть `%DATE% %TIME%`
  на русской локали;
- **опорные строки:** `TYPE=`, `Найден файл:`, `Локальный размер:`,
  `Remote:`, `SKIP`, `Режим: UPLOAD`, `Попытка N/M`, `SUCCESS`,
  `WinSCP exit code=`, `Файл успешно загружен`, `FAILED`, `END`.
  Незнакомые строки бот пропускает молча — дописывать своё можно,
  переименовывать перечисленное нельзя;
- **код возврата.** Ноль — рейс прошёл, остальное — упал. Бот пишет его
  в файл-метку рядом со своим журналом (`%ProgramData%\bot\copy\`), и
  это единственный признак, по которому «скрипт отработал» отличается от
  «процесс жил и исчез».

## Главная ловушка: «файл уже на приёмнике»

Пропускать базу можно **только** сверив размер, и сверять его надо
**строками**. Существование файла ничего не доказывает: оборванная
заливка по SFTP оставляет файл с правильным именем и неправильным
размером, и такой огрызок пропускался бы каждый следующий рейс —
навсегда. Копии как бы есть, а восстановить из них нечего.

Числами в `cmd` большие размеры не сравнить: и `set /a`, и `IF EQU`/`GEQ`
считают 32-битными знаковыми, а копия в 45 330 792 448 байт туда не
влезает — 42 ГБ и 2.5 ГБ оказываются «равны». В жизни это выглядело как
`Remote == Local. Файл уже полностью загружен. SKIP` при 2.59 ГБ на
приёмнике из 42.22 домашних.

Правильно так (десятичные записи равных чисел совпадают посимвольно):

```cmd
if "!RSIZE!"=="!SIZE!" goto :skip
```

И правило на все спорные случаи: **сомневаешься — заливай**. Не
разобрали размер, не нашли строку в выводе `ls`, ответил не тот сервер —
всё это ведёт в `UPLOAD`. Лишняя заливка стоит времени, пропущенная —
всей копии.

Бот сторожит это со своей стороны: у каждой базы, которую скрипт счёл
залитой или пропущенной, он сам смотрит размер на приёмнике и помечает
несовпадение знаком ❗ в разделе 📄 Журнал. Для этого у сервера-источника
должны быть заданы «Приёмник копий» (`copy_target`, `copy_target_root`).

Про кодировку журнала бот знает всё сам: он читает файл байтами и
декодирует построчно (UTF-8, CP866, CP1251) — `cmd` и WinSCP пишут в одну
и ту же дату разными кодировками. Менять `chcp` ради бота не нужно.

Подробности — в корневом `readme.md`, раздел «Копирование по готовности
копии (вместо планировщика)».

## Про обезличивание

Репозиторий публичный. В образцах не должно быть настоящих хостов,
доменов, адресов, имён баз и учётных записей: адреса — из `192.0.2.0/24`,
домен — `example.local`. Свои значения держите только в копии на сервере.
